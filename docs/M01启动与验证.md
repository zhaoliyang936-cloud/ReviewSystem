# ReviewSystem M01 启动与验证

本文记录 2026-11-07 的单机验证和复现步骤。M01 只提供工程基础；没有账号、题库或 AI 调用。启动后端要求数据库可连接，`/api/health` 仅表示应用进程已响应，不持续检查数据库健康。

## 依赖

设计基线及本机检查：JDK 21（本机 Azul 21.0.13）、Maven 3.9.16、Node 24.19.0（npm 11.17.0）、PostgreSQL 16.15、Spring Boot 3.5.16。前端直接依赖 Vue 3.5.22、Vue Router 4.5.1、Pinia 3.0.3、Vite 7.1.12；精确传递依赖见 `frontend/package-lock.json`。后端依赖由 Spring Boot 3.5.16 BOM 管理。数据库和仓库均独立于 xzs。

## 数据库与配置

准备一个 PostgreSQL 16.15 实例和空的独立数据库 `reviewsystem`，由该项目专用账号拥有。下面是在已有 PostgreSQL 管理员连接中执行的示例，须按本机权限调整；本次实际使用单独测试集群创建空库，以下角色创建步骤尚未验证：

```sql
CREATE ROLE reviewsystem LOGIN;
-- 在 psql 中用 \password reviewsystem 交互设置密码
CREATE DATABASE reviewsystem OWNER reviewsystem;
```

首次迁移前确认连接指向独立空库，并备份已有数据。PowerShell 中设置环境变量（密码由本人在本机输入，勿写入仓库）；`backend/.env.example` 不会自动加载：

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/reviewsystem'
$env:DB_USER = 'reviewsystem'
$env:DB_PASSWORD = Read-Host '数据库密码'
$env:AI_ENABLED = 'false'
```

启动后端时 Flyway 自动执行 `backend/src/main/resources/db/migration` 中尚未应用的版本；V1 为基础迁移，不创建业务表。检查 `flyway_schema_history` 的版本和成功状态。迁移失败时保留数据库与日志，核实原因和备份；不要删除库、表或修改已执行迁移以强行重试。必要时从备份恢复，或经审查新增前向修复迁移。

## 启动和检查

在仓库根目录分别使用两个 PowerShell 窗口：

```powershell
cd backend
mvn test
mvn spring-boot:run
```

```powershell
cd frontend
npm ci
npm test
npm run build
npm run dev -- --host 127.0.0.1 --strictPort
```

前端默认访问 http://127.0.0.1:5173/，开发服务器将 `/api` 代理至 http://localhost:8080；可在启动 Vite 前设置 `VITE_BACKEND_TARGET`。后端直接检查 http://localhost:8080/api/health。预览/生产部署需要另行配置同源 `/api` 反向代理；Vite 开发代理不用于生产。密钥不可使用 `VITE_` 前缀。

- 依赖解析：沙箱内 DNS 无法解析 Maven Central/npm；允许网络访问后 Spring Boot 3.5.16 和前端依赖可下载。没有更改设计版本。
- `npm install` 生成锁文件，`npm run build` 成功；`npm test` 两项通过；开发服务器在 127.0.0.1:5173 启动。
- 另一台机器启动与迁移：未执行，M01 的双环境验收尚未满足。
- 后端 `mvn test`：3 项通过（健康响应、404、405）。首次 `spring-boot:run` 插件依赖下载超时，重试后成功启动。
- 隔离测试集群使用 PostgreSQL 16.15、127.0.0.1:55432 和 `reviewsystem` 空库；Flyway 日志显示 V1 成功，查询 `flyway_schema_history` 得到 `1 | foundation | true`。本次测试集群使用本机信任认证，仅用于隔离测试，不应照搬到共享环境；测试后已停止，数据目录保留在工作区 `.environment-setup/reviewsystem-m01-pg2`。
- 后端 `/api/health` 和 Vite 代理 `/api/health` 均返回 `{"status":"UP"}`；前端入口 HTTP 200。未做浏览器页面人工验收。
- `npm ci` 在 Vite 运行时因 Windows 占用 esbuild 文件失败；停止 Vite 后离线重试成功。npm 提示 esbuild 安装脚本待批准，但本次构建通过。
- 本机 Maven 缓存目录受限，实际测试使用 `-Dmaven.repo.local=D:\软件工程职业实践\.environment-setup\m2-m01`；常规路径可写时不需要该参数。
- 后端 `mvn package` 成功，生成可执行 Spring Boot JAR；再次执行的 3 项测试通过。
