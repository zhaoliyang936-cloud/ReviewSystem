## 5. 复检与修复（第二轮）

首轮交付后按代码逐文件复检，发现 4 个实质缺陷并修复，均补了回归用例。

| 问题 | 现象与根因 | 修复 |
|---|---|---|
| 单字中文查询返回空 | `tokenize` 只对长度 ≥2 的 CJK 连续串切二元组，单字串不产生 token，`search` 见 `tokens.isEmpty()` 直接返回空列表——查询被丢弃而非未命中（`栈`、`队` 全空） | 单字 CJK 原字保留为 token；`MaterialSearchTest.singleCharacterChineseQueryStillMatches` |
| 存在草稿时无法撤回线上版本 | `withdraw` 校验 `latest.status == PUBLISHED` 后只更新 latest 行；编辑生成 v2 `DRAFT` 后 latest 是草稿，撤回返回 409，而 v1 仍在被检索 | 撤回对象改为 `max(version) where publication_status='PUBLISHED'`（`FOR UPDATE`），`expectedVersion` 仍比对 latest；`MaterialIntegrationTest.withdrawReachesPublishedVersionEvenWhenNewerDraftExists` |
| 撤回原因不落库 | 接口收 `reason` 却只做一次响应回显，刷新页面即丢失，无法追溯 | V12 新增 `withdraw_reason` / `withdrawn_by` / `withdrawn_at`，撤回事务内写入；详情对旧版本记录兜底读取最近一次原因 |
| 状态展示误导 | 列表/详情只暴露 latest 版本状态，`v2 DRAFT` 期间界面显示「草稿」，而线上仍是 v1 且可被检索，撤回按钮也随之消失 | 列表与详情新增 `publishedVersion`（`null` = 线上无内容），前端并排显示「最新版本」与「线上生效版本」，撤回按钮改为「存在生效版本即可点」 |
