# M02 身份与权限：运行和验证

M01 已在单机验证，第二台机器启动和迁移仍待验收。M02 不包含题库、作答、任务或 AI。

## 配置和初始化

按 M01 文档准备独立 PostgreSQL 数据库和连接配置，先备份已有数据库。启动时 Flyway 前向执行 V2，创建 `rs_user`、`rs_session`；不要修改已执行的迁移。账号用户名为 3–40 位 ASCII 字母、数字或下划线；密码至少 12 字符，UTF-8 不超过 72 字节。

首次启动时通过受保护的进程环境同时设置 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，系统仅在不存在管理员时创建一个管理员，使用数据库事务锁防止并发初始化；不会修改已有管理员。初始化后从部署环境移除这两个变量。禁止把真实密码放入仓库、命令历史或共享日志；若用户名已被占用启动会失败，需检查数据库。管理员不可通过学生注册创建，当前接口只允许禁用学生。管理员账号恢复和更换密码尚未提供操作界面，须规划受控运维流程。

`COOKIE_SECURE=true` 用于 HTTPS 部署（包括 HTTPS 反向代理），同时确保同源代理转发 `/api`，使用 TLS 且禁止绕过代理直接访问后端。默认 `false` 仅供本机 HTTP 开发；RSID 和 CSRF 使用的 JSESSIONID 均为 HttpOnly、SameSite=Lax。会话最长 30 分钟，服务端保存随机令牌的 SHA-256 摘要并在每次请求检查用户状态；退出和禁用会删除相应会话。过期记录当前不会自动清理，需安排定期清理 `rs_session` 中过期记录。CSRF token 使用服务端 HTTP 会话，后端重启后浏览器需重新获取 token；认证会话本身保存在数据库中。

所有状态变更，包括注册和登录，先 GET `/api/auth/csrf`，在返回的 `headerName` 指定的请求头中提交 `token`，同时保留浏览器 cookie；登录成功后 GET `/api/me`，退出 POST `/api/auth/logout`。`POST /api/admin/users/{id}/disable` 仅管理员可用；`GET /api/users/{id}` 只允许用户本人读取。后续作答、任务和辅导接口必须分别按真实业务对象的用户 ID 在服务端查询并检查归属，不能仅依靠前端或此账户接口。

登录失败限速按直接连接 IP 在单进程内记录：15 分钟内 5 次失败后暂时拒绝该 IP 的登录；重启会清空，NAT 可能影响共享 IP。当前不信任转发头；代理部署时直接连接 IP 通常是代理地址，应在受信任边界增加正确配置的网关限速；多实例需要共享限速器。注册未实现速率限制。应用不适合直接作为生产级大规模身份服务。

## 测试

设置 DB_URL、DB_USER、DB_PASSWORD 指向专用测试库，执行 `mvn test`（集成测试会应用迁移并创建、清理随机前缀测试用户）；前端执行 `npm test` 和 `npm run build`。不要对生产数据库运行集成测试。自动测试中的跨用户对象是 M02 账户资料，不是未实现的答卷或任务。浏览器实际登录流程、HTTPS 反向代理下 Secure cookie、两台机器部署及真实管理员初始化操作需人工验证。
