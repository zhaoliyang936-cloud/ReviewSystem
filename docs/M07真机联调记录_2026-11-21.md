## 4 失败项与原因定位

1. **第 6 项（刷新后草稿未还原）**：草稿从未以有效内容落库，`rs_task_item.draft_json` 是 JSON `null`（不是 SQL `NULL`），由三层原因叠加造成，最初判断的「刷新覆盖」不成立：
   - **触发点：`structuredClone` 克隆 Vue 响应式代理失败**。`ReviewTaskPage.vue` 的 `initial(i)` 用 `structuredClone(i.draft)` 复制草稿，而 `i.draft` 是 Vue 的响应式 `Proxy`，`structuredClone` 对 Proxy 直接抛 `DataCloneError`（`#<Object> could not be cloned`）。`load()` 的 `for (const i of task.value.items)` 因此当场中断，`answers` 只填到出错那一项之前，后续所有题项在 `answers` 里没有键。
   - **前端兜底对象游离**：`answers.value[item.value?.id] || {}` 在表项缺失时返回一个临时对象，`v-model` 把输入写进临时对象而不是 `answers`，`save()` 再从 `answers` 取值就是空。
   - **服务端接受空答案**：`ReviewTaskService.draft` 用 `writeNullable` 把缺失或 `null` 的 `answer` 直接写成 `jsonb 'null'` 入库，没有任何「必须是对象」的校验。
   三者叠加后的表现是「`PUT .../draft` 返回 `200`、`draftVersion` 递增、刷新后仍是空」。注意 `jsonb 'null'` 与 SQL `NULL` 在 psql 里都显示为 `null`，只看 `count(draft_json)` 会把前者误判成「有草稿」。
2. **第 13 项（管理员题图上传 `403 Access denied`）**：[api.js](file:///D:/软件工程职业实践/ReviewSystem/frontend/src/api.js#L4) 将 `csrf` 缓存在模块级变量 `let csrf` 中且只在 `!csrf` 时获取一次。学生登出（使旧 HTTP 会话失效）并由 `Home.vue` 登录 `admin` 后，`api.js` 仍持有登出前旧会话的 `csrf` 令牌，导致 `POST /api/admin/questions/31/assets` 携带过期 CSRF Token 被 Spring Security 拒绝为 `403`。
