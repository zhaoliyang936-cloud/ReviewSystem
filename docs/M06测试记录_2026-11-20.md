## 2. 规则版本

集中配置类为 `VersionedRecommendationConfig`，当前 `ruleVersion='v1'`。v1 参数：W/T/E 权重分别为 0.60/0.25/0.15，时间截断窗口 7 天，错误率窗口最近 5 条选中证据，冷却 24 小时，默认题数 10，复习/诊断默认槽位 8/2，复习初始知识点数 3，全新用户最多覆盖 5 个知识点，复习池门槛 n>=3。修改任一参数必须同步提升规则版本号。

固定算例：`final_score=30`，所以 `W=1-30/100=0.7`；`d=3.5` 天，所以 `T=min(3.5/7,1)=0.5`；最近 5 条选中证据中 2 错，所以 `E=2/5=0.4`。因此：

`P = 0.60×0.7 + 0.25×0.5 + 0.15×0.4 = 0.42 + 0.125 + 0.06 = 0.605`。

计算使用 `BigDecimal`，上述中间项不四舍五入。

## 4. 构造器注入缺陷与修复

首次执行环境因 Windows socket 10013（Permission denied）无法访问 `127.0.0.1:55434`，当时只完成 `mvn -DskipTests package`，未跑测试，记录如实标注为阻塞。

恢复端口访问后运行全量测试，暴露出一个**会让整个后端启动失败**的缺陷：

```
Failed to instantiate [RecommendationService]: No default constructor found
Caused by: java.lang.NoSuchMethodException: RecommendationService.<init>()
```

`RecommendationService` 同时存在 `(JdbcTemplate, VersionedRecommendationConfig)` 与包私有的 `(JdbcTemplate, VersionedRecommendationConfig, Clock)` 两个构造器，Spring 无法自动判定注入目标，`recommendationService` Bean 创建失败，导致所有 `@SpringBootTest` 上下文启动失败——M04 的 12 条、M05 的 7 条全部连带报错。`mvn -DskipTests package` 不启动上下文，因此打包成功掩盖了该问题；若直接 `mvn spring-boot:run`，应用同样无法启动。

修复方式：为供容器注入的双参构造器标注 `@Autowired`，三参构造器继续供测试传入固定 `Clock`。修复后 73 项全部通过。
