## 5 环境与复现

本机没有常驻 PostgreSQL 服务（`Get-Service` 无 `postgres*`，`D:\DevTools\pgsql` 下无 `data` 目录），数据在 Codex 建的一次性集群里：

```text
数据目录：D:\软件工程职业实践\.m04-audit-syntax-pg
端口：55434
启动：D:\DevTools\pgsql\bin\pg_ctl.exe -D "D:\软件工程职业实践\.m04-audit-syntax-pg" -l log.txt start
```

建库与导入：

```powershell
$env:PGCLIENTENCODING='UTF8'
D:\DevTools\pgsql\bin\psql.exe -h 127.0.0.1 -p 55434 -U postgres -d postgres -c "CREATE DATABASE reviewsystem;"

$env:DB_URL='jdbc:postgresql://127.0.0.1:55434/reviewsystem'
$env:DB_USER='postgres'
$env:DB_PASSWORD='postgres'
cd backend
.\scripts\import-questions.ps1 -Manifest .\scripts\question-manifest-19A.json -Report ..\import-report-19A.json
```

导入结果：

```text
第一次：total=31 imported=31 skipped=0 failed=0 exit=0
第二次：total=31 imported=0  skipped=31 failed=0 exit=0
```

迁移必须由应用启动时执行，不要用 psql 手工 `-f` 跑 V1—V5：那样 `flyway_schema_history` 不会写入，之后 Flyway 会以 "Found non-empty schema(s) public but no schema history table" 拒绝启动。

就绪查询：

```powershell
$env:PGCLIENTENCODING='UTF8'
D:\DevTools\pgsql\bin\psql.exe -h 127.0.0.1 -p 55434 -U postgres -d reviewsystem -v ON_ERROR_STOP=1 -f docs\M04题库就绪查询.sql
```

## 6 已知问题

1. **临时集群未固化**。数据目录在项目根，删目录等于清库。M04 联调前应把它迁到 `D:\DevTools\pgsql\data` 并注册为服务，或写进 `M01启动与验证.md` 作为约定的开发库。
2. **`M04题库就绪查询.sql` 原版无法执行**。`BEGIN TRANSACTION READ ONLY` 下 PostgreSQL 拒绝 `CREATE VIEW`（含 TEMP VIEW），实测退出码 3。已改为普通事务 + 末尾 `ROLLBACK`，脚本不写任何业务表。
3. **`structurally_valid` 是离线近似**。它按 `QuestionValidator` 的规则用 SQL 复刻，线上判定仍以 Java 校验器与 `/api/admin/question-coverage` 为准。当前实测两者都为"缺绑定 0、字段不完整 0"，口径一致；后续若校验器改规则，这里要同步。
4. **19 卷有 2 道题未导入**（AOE 网、平衡树/B-树/哈希综合），需要画图，导入脚本不支持附件，得在管理端手工建题后传图。
